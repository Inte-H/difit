# 지적 하나에는 fixup 커밋을 하나만 둔다

지적 스레드에는 "답이 왔다", "해결됐다" 같은 상태 칸이 없다. 화면은 `Review-Thread: <threadId>` 트레일러로 그 지적에 달린 fixup 커밋을 찾고, 거기에 리뷰어의 결정 기록을 합쳐서 매번 상태를 계산한다. 이렇게 하려면 지적 하나에 fixup이 하나여야 한다. 둘이 되면 어느 쪽이 판정할 답인지 가릴 근거가 없다. 그래서 판정 전에 같은 지적을 또 고쳤으면 새 커밋을 만들지 않고 앞의 fixup에 합치며, 거절된 fixup은 버리고 새로 만든다.

## 검토한 다른 길

같은 지적에 fixup을 여러 개 붙이도록 허용하고, 어느 것이 답인지 상태 파일에 따로 적는 길이 있었다. 비슷한 도구 github-os가 이 방식을 썼는데, 같은 대상에 fixup을 더 붙이는 단계에서 지적과 fixup의 일대일 관계가 스스로 깨졌다.

## 결과

한 커밋에 서로 다른 지적의 fixup이 여러 개 붙는 것은 정상이다. 트레일러가 서로 다르기 때문이다. 규칙이 묶는 것은 지적 하나당 개수뿐이다.
