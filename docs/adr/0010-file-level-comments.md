# 파일 전체에 단 지적은 위치에 줄 대신 `scope: "file"`을 적는다

"이 파일은 무슨 역할인가", "이 클래스를 둘로 나누자"처럼 특정 줄이 아니라 파일에 대한 지적이 있다. 지금까지는 모든 지적이 파일과 줄을 함께 가졌기 때문에 이런 지적도 아무 줄에나 달아야 했고, 화면에서도 에이전트에게 넘기는 글에서도 그 줄에 대한 지적처럼 읽혔다. 이제 파일 머리의 `파일 지적` 단추로 파일 전체에 지적을 단다.

저장하는 지적의 위치(`position`)는 두 모양 가운데 하나가 된다. 줄에 단 지적은 지금처럼 `{ "side": "new", "line": 12 }`이고, 파일 전체에 단 지적은 `{ "side": "new", "scope": "file" }`이다. `line`과 `scope`를 함께 적은 위치, `scope`가 `file`이 아닌 위치, 둘 다 없는 위치는 가져오기에서 거절한다. `side`는 줄 지적과 같이 남기고, diff가 지운 파일이면 `old`, 그 밖에는 `new`로 적는다. 에이전트가 파일의 어느 쪽 내용을 읽을지 줄 지적과 같은 규칙으로 정할 수 있게 하려는 것이다.

이 모양은 이미 저장된 지적과 가져오기 형식을 하나도 바꾸지 않는다. 브라우저에 저장된 지적, `commentImports`, 시작할 때 주는 `--comment` JSON, `difit comment add`가 받는 JSON 모두 줄 지적은 전과 똑같이 읽고, 파일 지적은 `scope`가 붙은 위치로 받는다. 저장 형식의 버전도 2 그대로다.

## 검토한 다른 길

- `line`을 빼기만 하기(`{ "side": "new" }`): 저장되는 글자는 가장 짧다. 하지만 `line`을 빠뜨린 가져오기가 오류 없이 파일 지적이 되어 버리고, JSON을 읽는 에이전트도 줄이 빠진 것인지 파일 전체인지 알 수 없다.
- `line`에 1 같은 값을 남기고 파일 지적 표시를 따로 두기(`{ "side": "new", "line": 1, "scope": "file" }`): 이 기능이 없는 옛 difit도 저장소를 읽다가 멈추지 않고 그 지적을 1번 줄 지적으로 보인다. 하지만 줄을 읽는 코드마다 표시를 먼저 확인해야 하고, 빠뜨린 곳은 컴파일러가 알려 주지 않은 채 파일 지적을 1번 줄 지적으로 다룬다. 줄을 읽는 곳이 화면, 서버, 프롬프트에 스무 곳이 넘는다.
- 리뷰 전체에 다는 지적(yoshiko-pg/difit#472)과 모양을 함께 정하기: 그 지적은 파일조차 없으니 `filePath`까지 비워야 해서 이번 변경보다 훨씬 넓다. 나중에 같은 `scope` 칸에 `review` 같은 값을 더하는 길은 이 모양으로도 열려 있다.

## 결과

- fixup을 걸 커밋은 보고 있는 화면의 커밋 가운데 그 파일을 마지막으로 바꾼 커밋이다. 그 화면의 커밋이 그 파일을 바꾸지 않았으면 그 화면의 마지막 커밋이다. 줄 지적과 달리 옛 쪽(`old`)이어도 같은 규칙을 쓴다. 지운 파일이면 지운 커밋이 고를 커밋이 된다. 커밋 목록에 없는 커밋(앞 회차의 fixup 따위)이 바꾼 것은 세지 않는다.
- 어느 화면에 보이는지는 줄 지적과 같다. 커밋 하나나 범위 화면에서 단 파일 지적은 그 화면과 고쳐 넣을 커밋이 든 화면, `전체` 화면에 보이고, 고쳐 넣을 커밋이 없는 화면에서는 숨는다. 보이는 화면인데 그 파일이 diff에 없으면 코멘트 패널에 `낡음`으로 남고 `이 지적을 단 화면으로` 단추가 뜬다. 파일 지적은 줄 내용으로 자리를 찾지 않으므로, 파일이 diff에 있는 한 낡음이 되지 않는다.
- 화면에서는 파일 머리 바로 아래, 코드 위에 그 파일의 파일 지적 카드가 모인다. 카드와 코멘트 패널에는 줄 번호 없이 파일 경로만 보이고, 패널에서는 같은 파일의 줄 지적보다 앞에 놓인다. 답글, 해결, 지우기, fixup의 승인과 거절은 줄 지적 카드와 같다. 직접 고치기는 고칠 줄이 없어 붙지 않는다. 키보드의 지적 사이 이동은 줄 지적만 오가고, 패널에서 파일 지적을 고르면 그 카드로 스크롤한다.
- `Copy All`, 지적 하나 복사, 리뷰를 끝낼 때의 출력, `difit comment get`의 텍스트 출력은 위치 줄에 `src/a.ts:L12` 대신 `src/a.ts`만 적는다. 옛 쪽 표시 `(old)`도 줄 지적에만 붙는다. `difit comment get --format json`, `difit comment wait`, 세션 메시지는 저장된 위치를 그대로 실어 `"position": { "side": "new", "scope": "file" }`가 된다.
- 이 기능이 없는 옛 difit을 같은 주소(포트)로 열면, 그 브라우저에 파일 지적이 저장된 리뷰에서 화면이 그려지지 않는다. 옛 코드가 위치의 `line`을 바로 읽기 때문이다. 줄 대신 1을 남기는 길이 이것을 피하지만, 위의 이유로 고르지 않았다.
- GitHub 풀 리퀘스트를 가져오는 `--pr`은 줄 지적만 가져오고, GitHub의 파일 지적은 지금처럼 건너뛴다.
