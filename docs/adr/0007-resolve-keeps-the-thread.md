# Resolve는 지적을 지우지 않고 해결 기록을 남긴다

원래 difit의 Resolve는 스레드를 저장소에서 지운다. 지우면 그 지적에 쌓인 대화와 리뷰 기록도 함께 사라져서, 무엇을 지적했고 어떻게 끝났는지 다시 볼 수 없다. 이 포크에서는 Resolve를 눌러도 스레드를 남겨 두고, 결정 기록에 `resolved`를 적는다. 다시 열면 `unresolved`를 적고, 둘 가운데 나중 기록을 따른다. 스레드에 상태 칸을 두지 않고 기록을 합쳐 상태를 계산한다는 원칙(0002)을 그대로 따른 것이다. 고정 커밋 없이 연 리뷰에서도 결정 기록은 같은 자리에 저장되므로 똑같이 동작한다.

upstream이 해결한 댓글을 지우게 된 계기는 yoshiko-pg/difit#236이다. 해결한 댓글이 아무 표시 없이 stdout에 계속 나와서 LLM이 헷갈린다는 보고였다. 보고자는 숨기거나, 보여 주되 해결됐다고 표시하자고 제안했고, 메인테이너는 숨기는 쪽을 골랐다. 그 뒤 스레드 기능을 넣은 yoshiko-pg/difit#249에서 Delete의 이름만 Resolve로 바뀌었고, 같은 PR의 작은 수정 커밋에서 "Resolve?" 확인 질문이 이유 없이 들어왔다. 되돌릴 수 없는 삭제라서 붙인 안전장치로 보인다.

그러니 지켜야 할 것은 해결된 지적이 AI에게 넘어가지 않는다는 점이고, 이것은 넘기는 곳에서 빼기만 해도 지킬 수 있다. 해결된 지적은 열린 지적 목록(`Copy All`과 열린 지적 수), 에이전트가 기다리는 목록(`difit comment wait`와 세션 메시지), 리뷰를 끝낼 때의 stdout 출력에서 빠진다. 지우지 않으므로 확인 질문도 필요 없어져 없앴다.

해결된 카드는 접힌 채 그 자리에 남고, 해결됨 표시가 붙는다. 해결과 다시 열기는 카드 헤더의 ✓ 버튼 하나로 오간다. 해결하면 눌린 모양이 되고, 다시 누르면 다시 열린다. 해결된 지적이 하나라도 있으면 도구 막대에 `해결된 지적 보기` 체크박스가 나오고, 처음에는 켜져 있다. GitHub 풀 리퀘스트와 GitLab 머지 리퀘스트 모두 해결한 스레드를 지우지 않고 접어 두며, 이 동작은 두 곳에서 가져왔다.

## 검토한 다른 길

- 스레드에 resolved 칸을 두기: 가장 단순하지만 스레드에 상태 칸을 두지 않는다는 0002와 어긋난다. 다른 기록과 따로 놀아서, 다시 여는 일과 해결하는 일이 엇갈릴 때 무엇을 따를지 정할 근거가 없다.
- 지우되 따로 모아 두기: 지운 스레드를 다른 목록에 옮겨 두는 방법이다. 저장할 곳이 하나 더 생기고, 다시 열 때 원래 자리로 되돌리는 일이 따로 필요하다.
- 해결을 승인과 합치기: 결정 기록의 종류는 늘지 않는다. 하지만 수정을 받아들인 지적과 수정 없이 끝난 지적을 가릴 수 없게 된다.
- Resolve를 아예 없애기: fixup으로 끝나는 지적은 승인과 접힘만으로 닫힌다. 하지만 말로 답을 받고 끝난 질문, 고칠 필요가 없다고 합의한 지적, 고정 커밋 없이 연 리뷰의 지적처럼 fixup이 생기지 않는 지적은 끝났다고 알릴 방법이 Resolve뿐이다.

## 결과

- 리뷰어가 해결된 카드에 답글을 달면 지적이 다시 열린다. 해결된 채로 두면 아직 할 말이 남았다는 답글이 어느 목록에도 들지 않기 때문이다. 다시 열린 뒤 에이전트에게 넘어가는지는 해결하기 전과 같이 리뷰 상태가 정한다. 수정 중이거나 다시 수정 중인 지적만 넘어간다. Gerrit도 스레드의 마지막 댓글이 해결 여부를 정하므로, 답글을 다는 일과 해결 여부를 정하는 일이 한 동작이다. 에이전트가 남기거나 시작할 때 주입된 메시지로는 다시 열리지 않는다.
- 해결과 따로, 리뷰어가 단 지적은 첫 글의 휴지통으로 답글까지 통째로 지울 수 있다. 해결은 「이 지적은 끝났다」이고 지우기는 「잘못 달았다」이므로, 엉뚱한 줄에 단 지적을 해결된 카드로 남기지 않으려는 것이다. 지운 지적도 저장소에서 없애지 않고 결정 기록에 `deleted`를 적어 숨긴다. 화면, 남은 지적 수, `Copy All`, `difit comment get`, 리뷰를 끝낼 때의 출력에서는 빠진다. 지적에 fixup이 남아 있으면 되돌림처럼 에이전트가 그 커밋을 빼야 하고, 에이전트가 넘겨받아 처리하던 지적이면 손을 떼야 한다. 서버가 이 둘을 wait로 알리려면 지운 지적의 글과 기록이 남아 있어야 한다. 원래 커밋에 접힌 지적은 빼낼 커밋이 없어 지울 수 없다. 해결된 지적은 JSON 출력에 계속 남는다. 파일 목록과 파일 칩의 댓글 수는 남은 일을 알리는 표시라서 해결되지 않은 지적만 세고, `해결된 지적 보기`를 켜도 같다.
- `/api/comments-json`과 `difit comment get --format json`은 해결된 스레드와 그 기록을 그대로 돌려준다. 기록을 읽는 쪽이 해결 여부를 스스로 가린다. 지운 스레드는 `difit comment get --format json`에서 빠지고, 화면이 서버와 맞추는 `/api/comments-json`에는 남는다.
- 해결된 지적에는 직접 고치기 버튼이 붙지 않는다. 서버도 해결된 지적을 답할 지적으로 보지 않는다.
- 단축키로 지적 사이를 옮길 때는 체크박스와 상관없이 해결된 지적을 늘 건너뛴다. 댓글 목록 창은 해결된 지적도 보여 주고, `d` 키는 묻지 않고 해결로 처리한다.
