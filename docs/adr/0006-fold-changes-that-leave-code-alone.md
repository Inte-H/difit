# 주석이나 공백만 바뀐 hunk는 tree-sitter로 가려 접고, fixup에는 배지만 단다

리뷰어가 중요한 변경에 시간을 쓰도록, 코드는 그대로 두고 주석이나 공백만 바꾼 hunk를 한 줄로 접는다. Anthropic의 글 "Redesigning source control at Anthropic"(2026-10-13)에서 생각을 빌렸다. 그 글은 자기들 리뷰 도구가 주석만 고친 변경과 민감한 로직 변경을 구분한다고만 쓰고, 어떻게 구분하는지는 밝히지 않는다.

판정은 서버에서 tree-sitter로 한다. hunk 안에서 바뀐 줄이 이어진 구간마다, 그 구간만 원래 파일에 적용해 다시 파싱한다. 주석을 뺀 구문 트리가 원래 파일과 같으면 주석만, 주석까지 같으면 공백만 바뀐 것이다. 파싱 오류가 나거나 지원하지 않는 언어이면 판정하지 않는다. 추측으로 "주석만"이라고 하지 않는 것이 이 기능의 전제다.

리뷰 diff에서는 "주석 변경 접기" 체크박스가 처음부터 켜져 있다. 접힌 자리에는 "주석 N줄 바뀜 · 펼치기" 한 줄이 남는다. 그래서 판정이 틀려도 무언가 숨겨졌다는 사실은 늘 보이고, 한 번 누르면 확인할 수 있다. 처음에는 꺼 두는 쪽을 생각했지만, 접힌 자리가 보이는 이상 꺼 둘 이유가 거의 없었다.

fixup에는 카드 머리에 "주석" 배지만 달고, 승인 버튼 옆에 경고는 띄우지 않는다. 코드를 고쳐 달라는 지적에 주석만 고친 fixup이 왔다면 제대로 답하지 않은 것이다. 하지만 주석을 고쳐 달라는 지적에는 주석만 고친 fixup이 올바른 답이고, 지적에는 무엇을 고쳐 달라는지가 따로 기록되지 않는다. 그 판단은 배지를 본 리뷰어가 한다. 자동 승인도 하지 않는다. 지적 하나에 fixup 하나를 리뷰어가 판정한다는 원칙(0002)을 바꾸는 일이기 때문이다.

## 검토한 다른 길

- prism 토큰 비교: difit에 이미 있는 구문 강조기라 새 의존성이 없다. 하지만 구문 분석기가 아니라 강조기여서, 시험해 보니 JSX 텍스트 안의 `// x`, bash `echo a#c`와 URL의 `#frag`, Python 3.12 f-string 안의 `#`를 주석으로 읽었다. difit은 Vue·Svelte·Astro를 빼고 줄 단위로 강조하므로, 여러 줄 문자열이나 heredoc 안의 `//`·`#`도 주석으로 읽었다. 이런 경우를 막는 규칙을 덧대면 그 규칙마다 반례가 생긴다.
- difftastic(`difft --ignore-comments`)을 불러 쓰기: 번들 크기는 그대로다. 하지만 119MB짜리 실행 파일을 따로 설치해야 켜진다. 또 파싱 실패와 코드 변경을 종료 코드로 가를 수 없어 안정판이 아닌 JSON 출력을 읽어야 한다.
- fixup에만 쓰기: 대상이 작고 hunk 위치를 맞출 필요가 없어 가장 싸다. 하지만 리뷰어가 접었다 펼 수 있어야 한다는 요구에는 리뷰 diff가 대상이어야 했다.
- 코드가 바뀐 파일을 목록 위로 올리기: 키보드 이동 순서가 바뀌고, 판정이 틀리면 코드 변경이 아래로 밀린다.
- 접은 hunk를 diff에서 아예 빼기: 화면은 깔끔하지만 무엇이 숨겨졌는지 알 수 없다.
- 민감한 경로 규칙(CODEOWNERS처럼 디렉터리를 정해 따로 드러내기): 판정과 따로 돌아가는 기능이고, 규칙을 어디에 저장할지(`.gitattributes` 속성, CODEOWNERS)부터 따로 정해야 해서 이번에는 넣지 않았다. CODEOWNERS는 누가 리뷰하는지를 적는 파일이라 위험한 곳을 가리키는 데 쓰기에는 뜻이 다르다.

## 결과

- 판정하는 언어는 TS/TSX/JS, Python, Go, Rust, Java, CSS, Bash다. grammar 패키지는 설치할 때 node-gyp-build가 돌고 크기도 커서 devDependencies에 두고, 빌드할 때 `.wasm` 파일만 `dist/tree-sitter`로 복사한다(6.7MB). runtime 의존성은 web-tree-sitter 하나다. grammar와 runtime은 함께 올려야 한다. 옛 grammar 묶음(`tree-sitter-wasms`)이 새 runtime에서 읽히지 않는 것을 확인했다.
- `@ts-ignore`, `eslint-disable`, `//go:build`, `# type: ignore`, shebang처럼 도구가 읽는 주석은 코드로 친다. 이런 주석을 지운 변경을 tree-sitter, prism, difftastic 모두 주석만 바뀐 것으로 판정했다. Python docstring은 실행 중에 `__doc__`으로 읽히므로 코드로 남는다.
- 판정은 파일마다 `/api/change-kinds/<path>`로 따로 받는다. parseDiff는 시작을 빠르게 하려고 파일 내용을 읽지 않는데, 생성 파일 판정과 같은 방식을 따랐다. 이 저장소의 실제 커밋 범위(파일 25개 가운데 판정 대상 23개)를 판정해 보니 파일당 대개 100ms 안이었고, 1800줄에 hunk가 17개인 파일이 330ms였다.
- 512KB가 넘는 파일, 바뀐 구간이 50개를 넘는 파일, grammar가 읽지 못하는 구문이 있는 파일은 판정하지 않는다. 예를 들어 tree-sitter-typescript 0.23.2는 타입 인자 안의 `typeof import('x')`를 읽지 못한다.
- 지적이 달린 hunk는 접지 않는다. 키보드 커서가 들어가거나 코멘트 입력창이 열린 hunk는 펼쳐 보인다. 펼친 hunk 위에는 머리줄이 `주석 N줄 바뀜 · 접기`로 남아 그 자리에서 다시 접는다. 커서가 안에 있어도 접히고, 커서가 움직이면 규칙대로 다시 펼친다. 코멘트 입력창이나 직접 고치기 창이 열린 동안에는 쓰던 내용이 가려지지 않도록 머리줄을 누를 수 없다. 주변 줄을 펼쳐 hunk 둘이 합쳐지면 판정도 합치고, 하나라도 코드가 바뀌었으면 접지 않는다.
